# Project: long technical document for the e-commerce microservices lab

The document is written in Markdown under `docs/`, next to the lab code. Several agents work in parallel, so every agent must follow the rules below. The reasoning behind each rule is in `docs/WORKFLOW.md`.

## Language
- Talk to the user in Vietnamese (address them as "bạn").
- Everything that is part of the deliverable is written in Vietnamese: `docs/sections/*.md`, `docs/GLOSSARY.md`, `docs/INDEX.md`. Use "chúng ta" for the narrator. Keep class names, packages, commands and widely used technical terms in English, following the terminology table in `docs/00-brief.md`.
- Everything else is written in English: `docs/00-brief.md`, `docs/lab-facts.md`, `docs/PROGRESS.md`, `docs/REVIEW.md`, `docs/POLISH-REPORT.md`, `docs/gaps/*`, and code comments in snippets.

## Sources of truth
- `docs/source/lab-plan.md`: the full lab content (exported from the chat/doc). **Read-only. Never edit.**
- `docs/lab-facts.md`: condensed confirmed facts (decisions, service names, versions, numbers). Every line cites a heading in `lab-plan.md`. Created by `doc-architect`.
- `docs/00-brief.md`: the shared contract (audience, voice, fixed terminology, running example, code conventions, section list). Every writer reads it before writing.
- If something is not in the sources, **do not invent it**. Record it in `docs/gaps/<id>.md` and keep writing the rest.

## File layout
```
docs/
  source/            # sources, read-only
  lab-facts.md       # condensed confirmed facts
  00-brief.md        # shared contract
  PROGRESS.md        # plan: id, file, source, budget, dependencies
  sections/NN-slug.md
  gaps/<id>.md       # missing information recorded by writers
  _snippets/<id>/    # small projects used to build-check code
  REVIEW.md          # reviewer output
  POLISH-REPORT.md   # polisher output
  GLOSSARY.md, INDEX.md
  dist/              # merged doc, docx, pdf (generated by scripts/build.sh)
```

## Status lives in each section's front matter
Every `docs/sections/NN-slug.md` starts with:
```
---
id: S03
title: Section title
status: draft        # draft | done | needs-fix
---
```
- Only the writer of a section changes its `status`. No agent edits `PROGRESS.md` while writers run in parallel.
- `bash scripts/status.sh` prints the status table from the front matter. `bash scripts/status.sh ready` lists sections that are ready to write (all dependencies are `done`).

## Writing rules
- Standard section template, with these Vietnamese headings in this order: `Mục tiêu` (goal), `Bối cảnh` (context), `Thiết kế` (design), `Code`, `Kiểm chứng` (verification), `Lỗi thường gặp` (common pitfalls), `Tóm tắt` (summary).
- Do not repeat content that belongs to another section. Refer to it as `§S04`.
- Stay within the word budget in `PROGRESS.md` (at most 20% deviation).
- Save the file early and write one subsection at a time, so an interrupted session loses as little as possible.

## Rules for code in the document
- If the code already exists in the lab repo (`src/...`), quote an excerpt from the real file and give its path. Never rewrite it from memory.
- New snippets must build: put them under `docs/_snippets/<id>/` and run `dotnet build`. If a snippet cannot be built or depends on infrastructure (Redis, RabbitMQ, ...), put `<!-- UNVERIFIED: reason -->` directly above that code block. Never claim code was run when it was not.
- Never put secrets, real connection strings or `.env` content in the document.

## Scope of a session
Each session does one job (plan, one wave of sections, polish, review, or fixes), then stops and reports briefly. Use `/clear` between sessions.
